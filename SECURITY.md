## Security Policy

Thank you for taking the time to improve the security of **Real Time Code Intelligence Gateway (RCIG)**.

This document describes how to report vulnerabilities and what you can expect from the maintainers.

---

## Supported Versions

Unless otherwise stated, **only the latest version** of RCIG is actively supported with security updates.

If you are using an older version, you may be asked to upgrade before we can fully investigate a reported issue.

---

## Reporting a Vulnerability

If you believe you have found a security vulnerability in RCIG:

1. **Do NOT open a public GitHub issue.**
2. Contact the maintainer privately via **email** or another private channel associated with the repository.
3. Provide as much detail as possible, including:
   - A description of the vulnerability.
   - Steps to reproduce the issue.
   - Any proof-of-concept code or configuration.
   - The impact you believe the vulnerability could have.

If you are unsure whether something is a security issue, please still report it privately — we will help assess the impact.

---

## What to Expect

After you report a vulnerability:

1. You should receive an acknowledgment within a reasonable time frame.
2. The maintainers will investigate and validate the issue.
3. If confirmed, we will:
   - Work on a fix.
   - Prepare a release (if needed).
   - Acknowledge your responsible disclosure (if you wish) in release notes or advisories.

We may contact you for additional information or clarification while we work on a fix.

---

## Responsible Disclosure

We kindly ask that you:

- Allow us a reasonable amount of time to resolve the issue before publicly disclosing it.
- Avoid exploiting the vulnerability beyond what is necessary to demonstrate its existence.
- Avoid accessing or modifying user data that does not belong to you.

Thank you for helping keep this project and its users safe.
